3) What Data Is Truly Required vs Optional

Required (to create an account + basic predictions)
	1.	Name (or nickname)
	2.	At least one goal
	3.	Cycle start anchor (choose one):
	•	Last period start date OR
	•	“I don’t know” → app uses default assumptions

That’s it.

Strongly recommended (better insights, still low friction)
	•	Cycle regularity (Regular/Irregular/Not sure)
	•	Average cycle length (if known)

Optional (high sensitivity / avoid gatekeeping)
	•	Date of birth (offer age range instead)
	•	Sexual health goal details (only if they choose it)
	•	Any diagnosis confirmation (PCOS/Endo) → never require proof; use supportive language

Best practice: allow “Skip for now” on anything except Name + Goal.

⸻

4) Goal-Based Branching (what happens after Goals)

Once they pick goals, you can tailor the next screens:
	•	Track my period → show cycle wheel + reminders emphasis
	•	Manage PCOS → add “symptom patterns + metabolic wellbeing” messaging
	•	Manage Endometriosis → add “pain tracking + flare support” messaging (trauma-informed)
	•	Track fertility → add ovulation window + temperature/OPK support later
	•	Sexual health → add optional privacy-first modules (consent, symptoms, testing reminders)
	•	General wellness → show daily check-in + insights

Implementation: store goals; adjust the copy/icons on screens 6–8 based on top goal, while keeping the same layout.

5) Error States + Empty States (Premium iOS feel)

Name screen
	•	Error (only on Next press):

	•	Empty state: placeholder only

Profile setup
	•	If user enters cycle length outside 15–60:
	•	“That doesn’t look right — most cycles fall between 15–60 days.”
	•	If last period date is in the future:
	•	“That date looks ahead — please choose a past date.”

Goals screen
	•	If none selected and they tap Continue:
	•	“Select at least one so I can tailor your experience.”

Network/account creation (later)
	•	“We couldn’t connect right now. Try again in a moment.”
	•	Button: Try again
	•	Secondary: Continue offline (if you support it)

Permissions (if you add later)
	•	Notifications:
	•	“Would you like gentle reminders?”
	•	“You can change this anytime in Settings.”

6) Accessibility + Inclusive Language Pass

Accessibility (must-haves)
	•	Tap targets ≥ 44x44pt (especially pills)
	•	Contrast:
	•	White text on gradient must pass contrast → add subtle dark overlay behind text if needed
	•	Dynamic Type friendly:
	•	Allow headings to wrap
	•	Avoid fixed heights on text blocks
	•	VoiceOver:
	•	Each pill announces “Selected/Not selected”
	•	Buttons have clear labels (“Continue”, “Get started”)
	•	Reduce Motion:
	•	If user prefers reduced motion → switch transitions to simple fades only

Inclusive language improvements (recommended copy tweaks)
	•	“Go hi” is cute and distinctive — keep it.
	•	“And what shall I call you?” ✅ warm and respectful
	•	For sensitive fields:
	•	Replace anything that sounds like interrogation (“Required for insights”) with:
“Only if you’re comfortable — this helps me personalise your experience.”
	•	For PCOS/Endo:
	•	Don’t imply diagnosis; use:
	•	“Support for PCOS”
	•	“Support for Endometriosis”
	•	Avoid gendered assumptions:
	•	Don’t say “women’s bodies” in onboarding copy; keep it “your body / your cycle”.
